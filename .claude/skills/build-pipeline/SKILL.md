# 审阅门控构建流水线

## 核心原则

任何项目或特性都必须走完「计划 → 审阅 → 执行 → 测试 → 收尾 → 汇报」全流程；两道门（审阅、测试）任一不达标即打回重做，不得跳级进入下一阶段。**违反流程的字面规定即违反其精神。**

## 适用范围与原则

- 本工作流用于 **Mine 工作空间** 的**快速验证**项目（一项目一文件夹）。
- **不回退原则**：计划与实现**不得设计「回退/兜底」路径**（如依赖失败改用替代库、工具缺失改用预编译产物、无头环境降级跳过）。依赖或工具缺失 → **直接补齐并走主路径**，或如实报告阻塞。审阅据此评估：技术可行性/风险与健壮性维度**不因「未提供回退方案」扣分**。
- **审阅门槛 90 分**（加权总分，满分 100）：≥90 放行，<90 打回。
- **CLI + 离屏渲染硬约束**仍强制（见①制定计划）。
- **隔离工作树原则**：执行与测试一律在 `.claude/worktrees/<任务名>` 的独立 `git worktree` 中进行，全部测试门全绿后**先合并回 `main`、再删除临时工作树**；详情见「⑤ 收尾」。

## 流程与门控

```
需求
  │
  ▼
① 制定计划 ──(必须含 CLI 模式 + 离屏渲染输出图像)──▶ 计划文档
  │
  ▼
② 审阅门 ◄──┐   review AGENT 五维加权打分
  │ ≥90 放行 │   <90 → 带反馈打回修订
  ▼          └──(循环直到 ≥90)
③ 执行 ──▶ [隔离工作树] implement AGENT 拉取/编译/写码
  │
  ▼
④ 测试门 ◄──┐   [隔离工作树内] test AGENT 全用例跑分
  │ 全绿放行 │   任一失败/跳过 → 修复后重测
  ▼          └──(循环直到 0失败0跳过)
⑤ 收尾 ──▶ finish AGENT:合并回 main → 删除临时工作树 → 清理/文档/git 干净
  │
  ▼
⑥ 汇报 ──▶ 回主会话输出最终结果
```

## 阶段细则

### ① 制定计划
- 先 `superpowers:brainstorming` 澄清需求，再 `superpowers:writing-plans` 产出计划。
- 计划文档落 `docs/superpowers/specs/`（设计）与 `docs/superpowers/plans/`（分阶段执行计划）。
- **硬约束（缺失则整份计划直接打回，不进入审阅打分）**：
  1. **CLI 模式**：必须有无头/脚本化入口，可脱离 GUI 交互运行。
  2. **离屏渲染输出图像**：必须能离屏渲染并落盘一张执行图像（如 PNG），供无头验收与 golden 对比。
     **离屏渲染 = Vulkan 离屏渲染核心（平台无关一套代码），不依赖窗口/显示服务（Xvfb/X11）**；
     平台差异只允许在软件光栅驱动选型（Linux=lavapipe / Windows=SwiftShader）。

### ② 审阅门（≥90 分放行）
- 派 `review` AGENT，按其输出契约返回五维得分 + 加权总分 + 逐维度扣分原因。
- 总分 ≥90 → 放行进入执行；<90 → 带反馈打回修订计划，重新审阅，循环至达标。

### ③ 执行（在隔离工作树内）
- **先开工作树**（由主会话执行，只此一次）：
  ```bash
  git -C <Mine 根> worktree add .claude/worktrees/<任务名> -b task/<任务名> main
  ```
  任务名取 `YYYYMMDD-<特性名>`（如 `20261105-ws-isolation`），与 `docs/superpowers/plans/` 里的计划同名。
- 派 `implement` AGENT，其 prompt **必须写明工作树绝对路径**，并约束：**所有读写只在该工作树内进行，禁止在 `Mine` 主工作区直接改文件**；严格按已通过审阅的计划执行：拉取/编译三方库、写业务代码，不得偏离计划中未经审阅的部分。
- 三方库池（`third_party/`、`.user-deps/`）已在 `.gitignore` 中，**工作树内不会自带**；需要时在工作树内按 `tools/setup-env.sh` 主路径重新拉取/编译（不回退、不复制主工作区的产物以免引入陈旧二进制）。

### ④ 测试门（100 分放行，在工作树内跑）
- 派 `test` AGENT，其 prompt 写明同一工作树路径，`ctest`/CLI/离屏 golden 全部在该工作树内执行。
- **100 分 = 全用例 0 失败、0 跳过、无回归**。任一失败/跳过 → 打回修复，重测，循环至全绿。

### ⑤ 收尾（合并 + 拆除工作树）
- 派 `finish` AGENT 按顺序完成，**顺序不可颠倒**：
  1. **合并回 main**：在工作树内提交（提交信息 `feat(<特性>): …`），随后在主工作区
     ```bash
     git -C <Mine 根> merge --no-ff task/<任务名> -m "merge: <任务名>"
     ```
     冲突 → 停工如实报告，不得在未验证状态下强推/覆盖。
  2. **删除临时工作树**：
     ```bash
     git -C <Mine 根> worktree remove .claude/worktrees/<任务名>
     git -C <Mine 根> branch -d task/<任务名>
     ```
     `worktree list` 必须只剩 `Mine` 主工作区；临时目录残留即收尾未完成。
  3. **主工作区复查**：合并后重新编译 + 重跑测试门，确认 `main` 上全绿（防止「工作树绿、合并后红」）。
  4. 清理临时产物、补文档、确认 `git status` 干净，产出收尾摘要。

### ⑥ 汇报
- 回到主会话，汇总：审阅得分、测试结果、变更清单、**合并提交号 + 工作树已删除证据**、遗留项，作为最终交付说明。

## 审阅五维评分表

| 维度 | 权重 | 满分要点 |
|---|---|---|
| 架构合理性 | 25% | 模块边界清晰、职责单一、接口解耦、符合 workspace 约定 |
| 需求完整性 | 25% | 需求全覆盖、验收标准可度量、可回溯到需求点 |
| 技术可行性 | 20% | 依赖可拉/可编、API 用法正确、版本兼容、无已知 blocker |
| 可测试性 | 15% | 每模块可独立测试、测试点明确、可注入 |
| 风险与健壮性 | 15% | 风险已识别、有错误处理、边界/异常路径已考虑 |

加权总分 = Σ(维度得分 × 权重)，满分 100，**≥90 通过**，<90 打回。

**评分口径（快速验证项目）**：技术可行性按「主路径能跑通 + 依赖可拉可编」评估；风险与健壮性按「主路径有基本错误处理、阻塞如实报告」评估。**不要求、也不加分于回退/兜底方案设计**。

## AGENT 输出契约

### review AGENT（审阅结果）
```
## 审阅结果
总分：{加权总分}/100 → 通过 / 打回
| 维度 | 权重 | 得分 | 扣分原因 |
| 架构合理性 | 25% | {x} | {原因} |
| 需求完整性 | 25% | {x} | {原因} |
| 技术可行性 | 20% | {x} | {原因} |
| 可测试性   | 15% | {x} | {原因} |
| 风险与健壮性 | 15% | {x} | {原因} |
[打回时] 修改建议：{逐条可执行}
```

### test AGENT（测试结果）
```
## 测试结果
用例 {通过}/{总数}，失败 {n}，跳过 {n}
结果：100 分（全绿）通过 / 打回
[打回时] 失败用例 + 修复建议
```

## 常见借口（红旗）

| 借口 | 事实 |
|---|---|
| 「计划明显没问题，跳过审阅」 | 审阅门是硬门，跳过即违规 |
| 「测试 90% 通过够用了」 | 测试门只有 100 分，任一失败即打回 |
| 「这项目不需要 CLI/离屏」 | CLI + 离屏是全局硬约束，无例外 |
| 「直接实现更快」 | 未经审阅的执行作废重来 |
| 「先做兜底方案更稳」 | Mine 是快速验证项目，不做回退；缺失即补齐或报阻塞 |
| 「差 1 分（89）也算过」 | <90 就是打回，无四舍五入 |
| 「这个环境只跑 Linux 就行」 | 渲染核心必须平台无关，双平台同一套测试与 golden；平台差异只在部署/驱动选型 |
| 「直接在主工作区改更快，工作树太麻烦」 | 执行与测试必须在 `.claude/worktrees/<任务名>` 内进行，主工作区只接收通过测试门的合并 |
| 「测试绿了，工作树留着下次用」 | 收尾必须合并 + 删除工作树，`worktree list` 只剩主工作区才算完成 |

## 常见错误
- 描述里省略「CLI + 离屏」硬约束 → 计划直接打回。
- 审阅只给总分不给逐维度扣分 → 无法定位问题，重审。
- 测试只报「通过/失败」不报失败用例与修复建议 → 无法闭环修复。
- 执行阶段擅自扩范围 → 超出审阅范围的改动视为未审阅。
- 计划里设计回退/兜底路径（替代库、预编译产物、降级跳过）→ 与快速验证原则冲突，修订移除。
- implement/test AGENT 的 prompt 没写明工作树路径，或 AGENT 跑回主工作区改文件 → 视为未隔离，该阶段作废重做。
- 只在工作树里测绿就汇报 → 合并后未在 `main` 复查即视为未交付。
- 合并后没删临时工作树（`.claude/worktrees/<任务名>` 残留）→ 收尾未完成。
